## Environment variables

To facilitate managing multiple configurations, Jeasx leverages layers of .env-files. This enables the use of different .env-files based on the NODE_ENV value, such as `.env.development` to override values from `.env` for development. The order of loading .env-files is similar to the well-known [dotenv-flow](https://github.com/kerimdzhanov/dotenv-flow) library (unlike dotenv-flow, `.env.local` is also loaded for `NODE_ENV=test`). To load the env-files into `process.env`, Jeasx makes use of the native implementation provided by Node.js via [process.loadEnvFile](https://nodejs.org/docs/latest/api/process.html#processloadenvfilepath) and a custom [utility function](https://github.com/jeasx/jeasx/blob/main/env.js).

- .env.[NODE_ENV].local _(e.g. .env.development.local or .env.production.local)_
- .env.[NODE_ENV] _(e.g. .env.development or .env.production)_
- .env.local
- .env
- .env.defaults

An existing environment variable will not be overwritten by subsequent environment files.

`NODE_ENV` itself must be set in the environment (e.g. by `jeasx dev` or your server). The files to load are chosen before any of them is read, so a `NODE_ENV` defined in a `.env` file doesn't select `.env.[NODE_ENV]` or `.env.[NODE_ENV].local`.

**Please note:** Jeasx only sets `NODE_ENV=development` automatically when running `jeasx dev`. For production or testing environments, you'll need to set the `NODE_ENV` environment variable to the desired value (e.g. `production` or `test`) depending on your requirements and workflows.

<Highlight title="Environment variables for client code" icon={html(IconAttention)}>
  For security reasons, environment variables are not accessible in frontend JavaScript by default.
  To expose specific variables, use the `ESBUILD_BROWSER_OPTIONS` configuration (see below).
</Highlight>

<a id="host-port"></a>

## Fundamental environment variables

### HOST

The hostname or IP address that the server should listen on. `jeasx start` defaults to `::`, which listens on all interfaces (IPv4 and IPv6). `jeasx dev` defaults to `localhost`, so other machines can't reach the dev server. If you run `jeasx dev` in a container or VM, or want to test from another device, set `HOST=::`.

### PORT

The port number that the server should listen on. Defaults to `3000`.

## Configure esbuild and Fastify via `jeasx.config.js`

The configuration object from `jeasx.config.js` is imported directly into both the build process and server runtime and provides essential options for `esbuild` and `Fastify`, allowing you to use the full power of JavaScript (e.g. package imports) to build advanced setups. All options can also be async functions, e.g. to import build-only plugins lazily, so they aren't loaded in production.

**Please note:** `jeasx.config.js` is not compiled by esbuild by default, so it can't contain JSX or TypeScript. If you need them, write your config as `jeasx.config.jsx` (or `.tsx`) and compile it with your own npm script:

```sh
esbuild jeasx.config.jsx --bundle --packages=external --outfile=jeasx.config.js --platform=node --format=esm --jsx=automatic --jsx-import-source=jsx-async-runtime
```

```js
// Every option may also be an async function returning a Promise.
export default {
  /** @type {() => import("esbuild").BuildOptions} */
  ESBUILD_SERVER_OPTIONS: () => ({}),

  /** @type {() => import("esbuild").BuildOptions} */
  ESBUILD_BROWSER_OPTIONS: () => ({}),

  /** @type {(fastify: import("fastify").FastifyInstance) => import("fastify").FastifyInstance | Promise<import("fastify").FastifyInstance>} */
  FASTIFY_SERVER: (fastify) => fastify,

  /** @type {() => import("fastify").FastifyServerOptions} */
  FASTIFY_SERVER_OPTIONS: () => ({}),

  /** @type {() => import("@fastify/send").SendOptions} */
  FASTIFY_SEND_OPTIONS: () => ({}),
};
```

### ESBUILD_SERVER_OPTIONS

Useful to enhance esbuild for compiling server code with existing plugins ([Jeasx config at GitHub](https://github.com/jeasx/jeasx/blob/main/build.js)). The esbuild website provides a detailed explanation of [all configuration options](https://esbuild.github.io/api/).

If you want to use MDX (with or without plugins), see [MDX](/jsx#mdx) for a complete configuration.

### ESBUILD_BROWSER_OPTIONS

Useful to configure build options for the browser bundle ([Jeasx config at GitHub](https://github.com/jeasx/jeasx/blob/main/build.js)), e.g. reconfigure the browser target of esbuild or define environment variables for JavaScript bundles. Full documentation at [esbuild website](https://esbuild.github.io/api/#target).

```js
export default {
  /** @type {() => import("esbuild").BuildOptions} */
  ESBUILD_BROWSER_OPTIONS: () => ({
    target: ["chrome130", "edge130", "firefox130", "safari18"],
    define: { "process.env.JOKES_API": `"https://expo.jeasx.dev/jokes/api/programming"` },
  }),
};
```

Async options are useful for plugins that are only needed for the build, e.g. a Sass plugin:

```js
export default {
  /** @type {() => Promise<import("esbuild").BuildOptions>} */
  ESBUILD_BROWSER_OPTIONS: async () => ({
    plugins: [(await import("esbuild-sass-plugin")).sassPlugin()],
  }),
};
```

### FASTIFY_SERVER

This allows you to enhance the functionality of the underlying [Fastify server](https://fastify.dev/docs/latest/Reference/Server/), e.g. registering plugins or an [error handler](/errors).

```js
export default {
  /** @type {(fastify: import("fastify").FastifyInstance) => import("fastify").FastifyInstance | Promise<import("fastify").FastifyInstance>} */
  FASTIFY_SERVER: (fastify) => fastify.register(import("@fastify/compress")),
};
```

<a id="fastify-server-options"></a>

### FASTIFY_SERVER_OPTIONS

Use these options to define the central configuration for the Fastify server.

[Fastify-Server options reference](https://fastify.dev/docs/latest/Reference/Server).

```js
export default {
  /** @type {() => import("fastify").FastifyServerOptions} */
  FASTIFY_SERVER_OPTIONS: () => ({
    // Keep the dev console quiet, log all requests in production.
    logger: { level: process.env.NODE_ENV === "development" ? "error" : "info" },
    bodyLimit: 2 * 1024 * 1024,
  }),
};
```

**Please note:** logging is turned off by default, as Jeasx passes no options to Fastify unless you configure them. Without the `logger` option, `request.log` and `fastify.log` write nothing, not even errors. The quickstart template already enables the logger as shown above.

### FASTIFY_SEND_OPTIONS

Use these options to serve static files, such as those located in the `public` directory or compiled frontend assets from `dist`.

[Fastify-Send options reference](https://github.com/fastify/send#options).

```js
export default {
  /** @type {() => import("@fastify/send").SendOptions} */
  FASTIFY_SEND_OPTIONS: () => ({
    immutable: process.env.NODE_ENV !== "development",
    maxAge: process.env.NODE_ENV === "development" ? 0 : "365d",
  }),
};
```

The `root` option is always set to the project directory by Jeasx, so don't set it yourself. Dotfiles (e.g. `public/.well-known/security.txt`) are ignored by default. Set `dotfiles: "allow"` if you want to serve them.

## Recommended Fastify plugins

Jeasx is built on the philosophy of providing a powerful core while pushing customizations to the user level. By avoiding opinionated defaults, Jeasx gives you the freedom to build a setup that is uniquely your own.

Need more features? No problem! Jeasx makes it easy to customize Fastify. Here are some Fastify plugins which help you to use common features in web development:

- Install [@fastify/formbody](https://github.com/fastify/fastify-formbody) if your project requires _POST_ form support.
- Install [@fastify/cookie](https://github.com/fastify/fastify-cookie) if you need to handle HTTP cookies.
- Install [@fastify/multipart](https://github.com/fastify/fastify-multipart) if your project handles file uploads.

```bash
npm install @fastify/formbody @fastify/cookie @fastify/multipart
```

Next, update your `jeasx.config.js` with the following configuration to customize your Fastify server instance:

```js
export default {
  /** @type {(fastify: import("fastify").FastifyInstance) => import("fastify").FastifyInstance | Promise<import("fastify").FastifyInstance>} */
  FASTIFY_SERVER: (fastify) =>
    fastify
      .register(import("@fastify/formbody"), {/* formbody options */})
      .register(import("@fastify/multipart"), {/* multipart options */})
      .register(import("@fastify/cookie"), {/* cookie options */}),
};
```

Because plugins like `@fastify/cookie` and `@fastify/multipart` extend the `request` and `reply` objects, you should add the following imports to `src/types.d.ts` (or a similar definition file in your project) to ensure proper TypeScript support for your editor:

```js
import "@fastify/cookie";
import "@fastify/multipart";
```

## Handle form submissions without `@fastify/formbody`

Although `@fastify/formbody` is commonly used for processing POST form data, Fastify provides the flexibility to define custom content type parsers manually. The following configuration demonstrates this approach:

```js
import querystring from "node:querystring";

export default {
  /** @type {(fastify: import("fastify").FastifyInstance) => import("fastify").FastifyInstance | Promise<import("fastify").FastifyInstance>} */
  FASTIFY_SERVER: (fastify) =>
    fastify.addContentTypeParser(
      "application/x-www-form-urlencoded",
      { parseAs: "string" },
      async (_request, body) => querystring.parse(body),
    ),
};
```

This configuration allows you to remove `@fastify/formbody` as a dependency.

**Please note:** The native Node.js querystring parser may have slightly higher latency than `@fastify/formbody`, but for the majority of applications, this performance trade-off is insignificant.
