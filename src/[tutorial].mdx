## <a id="create"></a>

## Step 1: Create the project

Create a new project from the quickstart template and start the dev server:

```bash
npm create jeasx@latest jeasx-tutorial
cd jeasx-tutorial
npm run dev
```

Open `http://localhost:3000/` to see the example app. Keep the dev server running for the whole tutorial. Jeasx rebuilds your code on every change, so you just have to reload your browser.

The template contains example pages which you won't need. Delete them in a second terminal:

```bash
rm -r "src/[index].jsx" "src/[...path].jsx" src/components src/browser
```

Your terminal will show some build errors now, because `src/[404].jsx` imports a layout which no longer exists. Don't worry, you'll fix this in the next step.

Here is what the project will look like at the end of this tutorial:

The most important rule is already visible here: **filenames in brackets are routes**. Everything else (components, libraries, ...) is just code you can import. Learn more about [routes](/routes).

## <a id="layout"></a>

## Step 2: Create a layout and use the context

Every page needs the same HTML skeleton. Create a layout component at `src/components/Layout.jsx`:

```jsx
import { html } from "jsx-async-runtime";

/**
 * @param {{ title: string, children?: JSX.Element }} props
 */
export default function Layout({ title, children }) {
  return (
    <>
      {html("<!DOCTYPE html>")}
      <html lang="en">
        <head>
          <meta charset="utf-8" />
          <meta name="viewport" content="width=device-width, initial-scale=1" />
          <title>{title} | Reading List</title>
          <link rel="stylesheet" href={`/index.css?v=${process.env.BUILD_ID}`} />
          <script type="module" src={`/index.js?v=${process.env.BUILD_ID}`}></script>
        </head>
        <body>
          <header>
            <a href="/" class="logo">
              📚 Reading List
            </a>
            <nav>
              <NavLink href="/">Books</NavLink>
              <NavLink href="/admin">Admin</NavLink>
            </nav>
          </header>
          <main>{children}</main>
        </body>
      </html>
    </>
  );
}

/**
 * @this {import("../types").ThisContext}
 * @param {{ href: string, children: JSX.Element }} props
 */
function NavLink({ href, children }) {
  const active = this.request.path === href;
  return (
    <a href={href} aria-current={active ? "page" : undefined}>
      {children}
    </a>
  );
}
```

A few things are different from React:

- Attributes use their HTML names, e.g. `class` instead of `className`.
- All text is escaped. To output trusted markup like the doctype as is, wrap it with `html()`.
- `process.env.BUILD_ID` is defined in `jeasx.config.js` at build time. It's appended to the asset URLs, so browsers load the new files after each deployment.

The `NavLink` component needs the current path to highlight the active link. Instead of passing the request down through all components, it reads the request from `this`. Jeasx passes the same `this` context to every route and component that renders a request. Which raises the question: who put the request there?

Have a look at `src/[...guard].js` from the template:

```js
/**
 * @param {import("./types").RouteProps} props
 */
export default function ({ request, reply }) {
  // Guards run before every route in this directory and below.
  // Provide request/reply via 'this' in components (e.g. Layout.jsx).
  this.request = request;
  this.reply = reply;
}
```

A **guard** runs before all routes in its folder and below. Because this guard lives in `src`, it runs for every request, so `this.request` is available everywhere. Every route and guard gets the Fastify `request` and `reply` objects as props.

## <a id="data"></a>

## Step 3: Store your books

To keep things simple, the books are stored in memory. Create a small module to manage them at `src/lib/books.js`:

```js
/**
 * @typedef {{ id: number, title: string, author: string, isbn: string, status: string }} Book
 */

export const STATUS = {
  "to-read": "To read",
  reading: "Reading",
  finished: "Finished",
};

// Each route is bundled separately, so a module variable would exist once per route.
// globalThis is shared by all routes and even survives hot reloads during development.
const store = /** @type {{ books?: Book[] }} */ (globalThis);

store.books ??= [
  {
    id: 1,
    title: "The Pragmatic Programmer",
    author: "David Thomas, Andrew Hunt",
    isbn: "9780135957059",
    status: "finished",
  },
  {
    id: 2,
    title: "Refactoring",
    author: "Martin Fowler",
    isbn: "9780134757599",
    status: "reading",
  },
  {
    id: 3,
    title: "Designing Data-Intensive Applications",
    author: "Martin Kleppmann",
    isbn: "9781449373320",
    status: "to-read",
  },
];

export function getBooks() {
  return store.books;
}

/**
 * @param {number} id
 */
export function getBook(id) {
  return store.books.find((book) => book.id === id);
}

/**
 * @param {Omit<Book, "id">} book
 */
export function addBook(book) {
  const id = Math.max(0, ...store.books.map((book) => book.id)) + 1;
  store.books.push({ id, ...book });
  return id;
}

/**
 * @param {number} id
 */
export function deleteBook(id) {
  store.books = store.books.filter((book) => book.id !== id);
}

/**
 * @param {number} id
 * @param {string} status
 */
export function updateStatus(id, status) {
  const book = getBook(id);
  if (book && Object.hasOwn(STATUS, status)) {
    book.status = status;
  }
}
```

As the filename has no brackets, this module is not exposed as a route. It's just a regular module you can import anywhere.

<Highlight title="Why globalThis instead of a module variable?" icon={html(IconAttention)}>
  Jeasx bundles each route into its own file. A module imported by two routes is therefore loaded
  twice, and each route would see its own copy of a variable. `globalThis` is shared by all routes,
  so it's the place for shared objects like caches, connection pools or, as here, a small in-memory
  store. As a bonus, it survives hot reloads during development. For a real app, you'd store the
  books in a database instead, so they survive a restart of the server.
</Highlight>

## <a id="home"></a>

## Step 4: Build the home page

`src/[index].jsx` answers requests for `/`. Like any route, it is a function which returns JSX:

```jsx
import Layout from "./components/Layout";
import { getBooks, STATUS } from "./lib/books";

/**
 * @param {import("./types").RouteProps} props
 */
export default function ({ request }) {
  const status = request.query["status"];
  const books = getBooks().filter((book) => !status || book.status === status);

  return (
    <Layout title="My books">
      <h1>My books</h1>
      <p class="filter">
        <a href="/" aria-current={!status ? "page" : undefined}>
          All
        </a>
        {Object.entries(STATUS).map(([key, label]) => (
          <a href={`/?status=${key}`} aria-current={status === key ? "page" : undefined}>
            {label}
          </a>
        ))}
      </p>
      {books.length === 0 ? (
        <p>No books found.</p>
      ) : (
        <ul class="books">
          {books.map((book) => (
            <li>
              <a href={`/books/${book.id}`} style={`view-transition-name: book-${book.id}`}>
                {book.title}
              </a>{" "}
              by {book.author} <span class={`badge ${book.status}`}>{STATUS[book.status]}</span>
            </li>
          ))}
        </ul>
      )}
    </Layout>
  );
}
```

Open `http://localhost:3000/` and click the filters. Some things to notice:

- Routes are plain functions which receive the request and return JSX. If you need to load data asynchronously, simply make the function `async` and `await` the data.
- Query parameters are available via `request.query`, e.g. `/?status=reading`.
- There is no client-side JavaScript involved. Jeasx renders plain HTML on the server, so the page is fast and works everywhere.

## <a id="dynamic"></a>

## Step 5: Show book details with a dynamic route

Every book needs its own page at `/books/1`, `/books/2` and so on. Instead of creating a file for each book, create a **dynamic route** at `src/books/[...path].jsx`. It answers all requests below `/books`:

```jsx
import Layout from "../components/Layout";
import { getBook, STATUS } from "../lib/books";

/**
 * @param {import("../types").RouteProps} props
 */
export default function ({ request }) {
  // "/books/2" => 2
  const id = Number(request.path.split("/").at(-1));
  const book = getBook(id);

  // Return nothing, so the request is passed on to the [404] route.
  if (!book) {
    return;
  }

  return (
    <Layout title={book.title}>
      <a href="/">&laquo; All books</a>
      <article class="book">
        <div>
          <h1 style={`view-transition-name: book-${book.id}`}>{book.title}</h1>
          <p>
            by {book.author} <span class={`badge ${book.status}`}>{STATUS[book.status]}</span>
          </p>
          <BookDetails isbn={book.isbn} />
        </div>
        <img
          src={`https://covers.openlibrary.org/b/isbn/${encodeURIComponent(book.isbn)}-M.jpg`}
          alt=""
          width="180"
          class="cover"
        />
      </article>
    </Layout>
  );
}

/**
 * @param {{ isbn: string }} props
 */
async function BookDetails({ isbn }) {
  try {
    const response = await fetch(
      `https://openlibrary.org/search.json?isbn=${encodeURIComponent(isbn)}&fields=first_publish_year,number_of_pages_median,subject&limit=1`,
    );
    const [details] = (await response.json()).docs;
    return (
      <dl>
        <dt>First published</dt>
        <dd>{details.first_publish_year}</dd>
        <dt>Pages</dt>
        <dd>{details.number_of_pages_median}</dd>
        <dt>Subjects</dt>
        <dd>{details.subject?.slice(0, 5).join(", ")}</dd>
      </dl>
    );
  } catch {
    return <p>No details available.</p>;
  }
}
```

Click on a book on the home page to see the result. Two essential features are at work here:

**Return nothing to pass the request on.** If a book doesn't exist (e.g. `/books/99`), the route returns `undefined`. Jeasx then tries the next matching route, which ends at the 404 page you'll create in the next step.

**Async components and streaming.** `BookDetails` is an async component which fetches data from Open Library. You don't need any hooks or loaders. Just use it like any other component. Jeasx streams the page to the browser while it renders, so the header and title arrive immediately, while the details follow as soon as the API answers.

Because the page has already been sent in part, an error in `BookDetails` can't turn into a nice error page anymore. That's why the component catches its own errors and shows a fallback. Learn more about this in [Error handling](/errors#streaming).

## <a id="api"></a>

## Step 7: Provide a JSON API

Other apps may want to use your reading list, too. Create `src/api/[books.json].js`:

```js
import { getBooks } from "../lib/books";

/**
 * @param {import("../types").RouteProps} props
 */
export default function ({ reply }) {
  reply.header("Access-Control-Allow-Origin", "*");
  return getBooks();
}
```

When a route returns an object or an array instead of JSX, Jeasx sends it as JSON. Use the `reply` object to set headers, status codes and more. As the name of the route ends with `.json`, the URL does too:

```bash
curl http://localhost:3000/api/books.json
```

The `[health].json` route from the template shows an even simpler way: a JSON file with brackets is served as is at `/health`.

## <a id="admin"></a>

## Step 8: Add a protected admin area

Now let's add a page to manage your books. Only you should be able to use it, so it's protected by a login form. Once you've logged in, a cookie remembers you.

### Install a Fastify plugin

Jeasx keeps its core lean. Cookies are handled by the official [@fastify/cookie](https://github.com/fastify/fastify-cookie) plugin, so install it first:

```bash
npm install @fastify/cookie
```

Then register the plugin in `jeasx.config.js`. The template already registers a parser for HTML forms there, which makes submitted forms available via `request.body`. Just add the plugin to the chain:

```js
FASTIFY_SERVER: (fastify) =>
  // Required only if you want to process form submissions via POST requests.
  fastify
    .addContentTypeParser(
      "application/x-www-form-urlencoded",
      { parseAs: "string" },
      async (_request, body) => querystring.parse(body),
    )
    // Read and write cookies, signed with a secret (see `src/admin`).
    .register(import("@fastify/cookie"), { secret: process.env.COOKIE_SECRET }),
```

To get autocompletion for the new cookie functions of `request` and `reply` in your editor, add the following import to `src/types.d.ts`:

```ts
import "@fastify/cookie";
```

### Define secrets in `.env`

Passwords and secrets don't belong in your code. Create a `.env` file in the project root:

```bash
ADMIN_PASSWORD=secret
COOKIE_SECRET=replace-me-with-a-long-random-string
```

The cookie will be signed with `COOKIE_SECRET`, so nobody can fake it. Please use a long random string here, e.g. created with `openssl rand -hex 32`.

Jeasx loads `.env` files automatically into `process.env`, but only when the server starts. The same applies to `jeasx.config.js`. So restart the dev server now: stop it with `Ctrl+C` and run `npm run dev` again. You can use different files for each environment, e.g. `.env.production`. See [configuration](/configuration#environment-variables) for details.

### Protect a folder with a guard

Create `src/admin/[...guard].js`. This guard runs before every route below `/admin`, so all admin pages are protected in one place:

```js
/**
 * @param {import("../types").RouteProps} props
 */
export default function ({ request, reply }) {
  // The login page must be reachable without being logged in.
  if (request.path === "/admin/login") {
    return;
  }

  // Only accept the cookie if its signature is valid, so nobody can fake it.
  const { valid, value } = request.unsignCookie(request.cookies.user ?? "");
  if (!valid) {
    return reply.redirect("/admin/login", 303);
  }

  // Objects returned by a guard are passed as props to all routes below.
  return { user: value };
}
```

A guard can do three things:

1. **Return nothing** to let the request pass, like the guard in `src/[...guard].js`. Here, it lets everybody see the login page.
2. **Return a response** (JSX, a string, ...) or send one via `reply` to answer the request itself. No other route runs. Here, it redirects you to the login page if you are not logged in.
3. **Return an object** whose entries are passed as **props** to all routes below. Here, every admin route receives a `user` prop.

### Log in and log out

Create the login page at `src/admin/[login].jsx`. If the password is correct, it sets the signed cookie and redirects you to the admin page:

```jsx
import { createHash, timingSafeEqual } from "node:crypto";
import Layout from "../components/Layout";

/**
 * @param {import("../types").RouteProps} props
 */
export default function ({ request, reply }) {
  let error = "";

  if (request.method === "POST") {
    const { password } = /** @type {Record<string, string>} */ (request.body ?? {});

    if (isValidPassword(password)) {
      reply.setCookie("user", "admin", {
        path: "/admin",
        signed: true, // Signed with COOKIE_SECRET, so it can't be faked.
        httpOnly: true, // Not readable by JavaScript in the browser.
        sameSite: "lax", // Not sent with forms posted from other sites.
        secure: "auto", // Only sent via HTTPS, if the site uses HTTPS.
        maxAge: 60 * 60 * 8, // Log out automatically after 8 hours.
      });
      return reply.redirect("/admin", 303);
    }

    reply.status(401);
    error = "Wrong password, please try again.";
  }

  return (
    <Layout title="Log in">
      <h1>Log in</h1>
      {error && <p class="error">{error}</p>}
      <form method="post" class="card">
        <label>
          Password <input type="password" name="password" required autofocus />
        </label>
        <button class="primary">Log in</button>
      </form>
    </Layout>
  );
}

/**
 * Compare in constant time, and never accept a login if no password is configured.
 * @param {unknown} password
 */
function isValidPassword(password) {
  const expected = process.env.ADMIN_PASSWORD;
  if (!expected || typeof password !== "string") {
    return false;
  }
  // Hash both sides so they have equal length, as timingSafeEqual requires.
  const hash = (/** @type {string} */ value) => createHash("sha256").update(value).digest();
  return timingSafeEqual(hash(password), hash(expected));
}
```

`isValidPassword` compares the passwords in constant time with `timingSafeEqual`, so an attacker can't guess the password from how long the check takes. It also refuses every login if `ADMIN_PASSWORD` isn't set. Thanks to `maxAge`, the cookie expires after 8 hours, so you are logged out automatically.

Logging out is even simpler. Create `src/admin/[logout].js`, which removes the cookie and sends you back to the home page:

```js
/**
 * @param {import("../types").RouteProps} props
 */
export default function ({ request, reply }) {
  // Only log out via the form, not by simply opening the URL.
  if (request.method !== "POST") {
    return;
  }

  reply.clearCookie("user", { path: "/admin" });
  return reply.redirect("/", 303);
}
```

The route only answers `POST` requests, which are sent by the logout button you'll add in a moment. For all other requests, it returns nothing, so the request ends up at the 404 page.

### Handle a form

Create the admin page at `src/admin/[index].jsx`. The same route shows the page (`GET`) and processes its forms (`POST`). A hidden `action` field tells the forms apart: add a book, change its status or delete it. The logout button at the top is a small form, too. It posts to `/admin/logout` via its `action` attribute.

```jsx
import Layout from "../components/Layout";
import { addBook, deleteBook, getBooks, STATUS, updateStatus } from "../lib/books";

/**
 * @param {import("../types").RouteProps & { user: string }} props
 */
export default function ({ request, reply, user }) {
  if (request.method === "POST") {
    const form = /** @type {Record<string, string>} */ (request.body ?? {});

    if (form.action === "delete") {
      deleteBook(Number(form.id));
    } else if (form.action === "status") {
      const id = Number(form.id);
      updateStatus(id, form.status);
      // Jump back to the updated book, so you can see the change.
      return reply.redirect(`/admin?updated=${id}#book-${id}`, 303);
    } else if (form.title?.trim() && form.author?.trim()) {
      const id = addBook({
        title: form.title.trim(),
        author: form.author.trim(),
        // Keep only characters that can appear in an ISBN.
        isbn: form.isbn?.replace(/[^0-9X]/gi, "").toUpperCase() ?? "",
        status: Object.hasOwn(STATUS, form.status) ? form.status : "to-read",
      });
      // Jump to the new book, so you can see it was added.
      return reply.redirect(`/admin?added=${id}#book-${id}`, 303);
    } else {
      reply.status(400);
      return <AdminPage user={user} error="Please enter a title and an author." form={form} />;
    }

    // Redirect after POST, so reloading the page doesn't submit the form again.
    return reply.redirect("/admin", 303);
  }

  return (
    <AdminPage
      user={user}
      updated={Number(request.query["updated"])}
      added={Number(request.query["added"])}
    />
  );
}

/**
 * @param {{ user: string, error?: string, form?: Record<string, string>, updated?: number, added?: number }} props
 */
function AdminPage({ user, error, form = {}, updated, added }) {
  const books = getBooks();

  return (
    <Layout title="Admin">
      <h1>Manage books</h1>
      <form method="post" action="/admin/logout" class="logout">
        Logged in as {user}.<button>Log out</button>
      </form>

      <h2>Add a book</h2>
      {error && <p class="error">{error}</p>}
      <form method="post" class="card">
        <label>
          Title <input name="title" value={form.title} required />
        </label>
        <label>
          Author <input name="author" value={form.author} required />
        </label>
        <label>
          ISBN <input name="isbn" value={form.isbn} />
        </label>
        <label>
          Status <StatusSelect value={form.status} />
        </label>
        <button class="primary">Add book</button>
      </form>

      <h2>All books</h2>
      <ul class="books">
        {books.map((book) => (
          <li id={`book-${book.id}`}>
            <span class="title">{book.title}</span>
            <div class="actions">
              {book.id === updated && <span class="saved">✓ Saved</span>}
              {book.id === added && <span class="saved">✓ Added</span>}
              <form method="post">
                <input type="hidden" name="action" value="status" />
                <input type="hidden" name="id" value={book.id} />
                <StatusSelect value={book.status} />
                <button>Save</button>
              </form>
              <form method="post" data-confirm={`Delete "${book.title}"?`}>
                <input type="hidden" name="action" value="delete" />
                <input type="hidden" name="id" value={book.id} />
                <button class="danger">Delete</button>
              </form>
            </div>
          </li>
        ))}
      </ul>
    </Layout>
  );
}

/**
 * @param {{ value?: string }} props
 */
function StatusSelect({ value }) {
  return (
    <select name="status">
      {Object.entries(STATUS).map(([key, label]) => (
        <option value={key} selected={value === key}>
          {label}
        </option>
      ))}
    </select>
  );
}
```

Open `http://localhost:3000/admin`. As you are not logged in yet, you are redirected to the login page. Log in with the password `secret`, add your favorite book and change the status of another one. After adding a book or saving a status, the redirect jumps to the book via its anchor in the URL (e.g. `#book-2`) and passes `?added=2` or `?updated=2`, so the page can confirm the change. You'll see your changes on the home page and in the JSON API. When you're done, click "Log out".

This is the Jeasx way: a lean core, plus the full power of [Fastify](https://fastify.dev) and [esbuild](https://esbuild.github.io) if you need more. Need file uploads, rate limiting or sessions? Just register another [Fastify plugin](/configuration#recommended-fastify-plugins).

document.querySelectorAll("form[data-confirm]").forEach((form) => {

Your layout already links both files. They are served at `/index.css` and `/index.js`, without `browser` in the URL. Why? esbuild builds all `index.*` files below `src` and keeps their folder structure, but relative to the deepest folder they all have in common. As both files live in `src/browser`, this common folder is `src/browser` itself, so it doesn't show up in the URL. The folder name `browser` is just a convention: you could also put your assets directly in `src` or in any other folder. Just keep in mind that the URLs change once your assets are spread over several folders. If you add `src/admin/index.js`, for example, the common folder becomes `src`, and your files are served at `/browser/index.css`, `/browser/index.js` and `/admin/index.js`. That's why it's a good idea to keep all browser assets in one folder.

Reload the page to see the styles. In the admin area, the CSS selector `:target` now highlights the book you've just updated, and deleting a book asks for confirmation first. On the detail page, an animated placeholder is shown while the cover image loads. Once the image has loaded, the script adds the class `loaded` and the cover fades in.

Opening a book is animated now, too. `@view-transition` turns on [view transitions](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API) between the pages of your site. The link in the list and the heading on the detail page share the same `view-transition-name` (e.g. `book-2`), so the browser moves the title from the list into the heading while the rest of the page cross-fades. Two details: in Jeasx, the `style` attribute takes a plain string, and the link is an `inline-block`, because a title which wraps over several lines can't be animated. Browsers without support for view transitions simply open the page as usual.

You can import CSS from other files, use npm packages in your scripts or add esbuild plugins (e.g. for Sass or Tailwind) in `jeasx.config.js`. Files which don't need processing, like images or `robots.txt`, belong in the `public` folder. See [CSS & JavaScript](/browser) for more details.

## Step 10: Run in production

So far, you've used the dev server. For production, build your app once and start the server:

```bash
npm run build
npm start
```

The build minifies your code and creates an index of all routes and files, so the server starts quickly and doesn't scan your project for each request. Remember to set `NODE_ENV=production` on your server, so `.env.production` files are used and Fastify logs requests (see `jeasx.config.js`).

## What you've learned

Congratulations, you've built your first Jeasx app! Let's recap:

- Files with **brackets** are routes: `[index]` for folders, named routes like `[books.json]`, dynamic `[...path]` routes and `[404]` pages. All other files are regular modules.
- Routes and components are **functions which return JSX**. They can be `async`, and pages are streamed to the browser while they render.
- Every route gets the Fastify **`request` and `reply`** as props. Return JSX for HTML, or objects for JSON.
- **Guards** run before routes. Use them to share data via `this`, protect folders or pass props to routes.
- `index.css` and `index.js` files in `src` are bundled for the **browser**. Static files go into `public`.
- `.env` files and `jeasx.config.js` let you **configure** everything, using the full power of Fastify and esbuild.

Want to see more? The [Expo](https://expo.jeasx.dev) shows a lot of examples, e.g. for cookies, file uploads, HTMX or Preact. Or continue with the essentials to learn all the details.
